# Test Data Directory

This directory stores YAML files and other test data referenced in BDD scenarios.

## Structure

```
test_data/
├── tasks/
│   ├── simple_task.yaml          # Basic task definition
│   ├── complex_task.yaml         # Task with multiple steps
│   └── parameterized_task.yaml   # Task with parameters
├── pipelines/
│   ├── simple_pipeline.yaml
│   └── multi_task_pipeline.yaml
├── pipelineruns/
│   └── basic_pipelinerun.yaml
└── triggers/
    ├── eventlistener.yaml
    ├── triggerbinding.yaml
    └── triggertemplate.yaml
```

## Usage in Scenarios

### Scenario Outline with Test Data

```gherkin
Scenario Outline: Create tasks from various YAML definitions
  Given the user is logged into openshift console with auth kube:admin
  When the user creates a task from YAML file "<yaml_file>"
  Then the task "<task_name>" should appear in the task list
  And the task should have "<step_count>" steps

  Examples:
    | yaml_file              | task_name     | step_count |
    | simple_task.yaml       | simple-task   | 1          |
    | complex_task.yaml      | complex-task  | 3          |
    | parameterized_task.yaml| param-task    | 2          |
```

### Step Definition Usage

```python
@when(parsers.parse('the user creates a task from YAML file "{yaml_file}"'))
def create_task_from_yaml(
    page: Dict[str, Any], yaml_file: str, playwright_event_loop: asyncio.AbstractEventLoop
) -> None:
    # Load YAML file from test_data directory
    import os
    from pathlib import Path

    test_data_dir = Path(__file__).parent.parent.parent / "framework" / "resources" / "test_data" / "tasks"
    yaml_path = test_data_dir / yaml_file

    with open(yaml_path, "r") as f:
        yaml_content = f.read()

    async def _step() -> None:
        await page["tasks"].create.fill_yaml_editor(yaml_content)
        await page["tasks"].create.click_create()

    run_async(playwright_event_loop, _step())
```

## File Naming Convention

- Use lowercase with underscores: `simple_task.yaml`
- Include resource type in name: `task`, `pipeline`, `pipelinerun`
- Descriptive names: `multi_step_task.yaml` not `task1.yaml`
- Version if needed: `task_v1.yaml`, `task_v2.yaml`

## YAML Template Guidelines

### Tasks

```yaml
apiVersion: tekton.dev/v1
kind: Task
metadata:
  name: {{ task_name }}  # Will be used for verification
spec:
  steps:
    - name: {{ step_name }}
      image: registry.redhat.io/ubi9/ubi-minimal
      script: |
        {{ script_content }}
```

### Pipelines

```yaml
apiVersion: tekton.dev/v1
kind: Pipeline
metadata:
  name: {{ pipeline_name }}
spec:
  tasks:
    - name: {{ task_name }}
      taskRef:
        name: {{ task_ref }}
```

## Generated by test-from-intent Skill

When the `test-from-intent` skill generates tests, it will:
1. Analyze the plain English intent
2. Determine required test data
3. Generate realistic YAML files here
4. Reference them in Scenario Outlines
5. Create corresponding step definitions

**Example**:
```
Input: "Create a task with echo step, validate creation"

Generated Files:
- framework/resources/test_data/tasks/echo_task.yaml
- tests/features/task_creation.feature (with Scenario Outline)
- tests/steps/test_task_creation_steps.py
```
